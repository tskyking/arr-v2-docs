## Deliberate simplifications and assumptions

- Four main shift states: In progress, Submitted, Needs attention, Closed. Review/correction events remain history, not extra approval gates.
- Optional questions and context are collapsed. SOP readiness is an explicit answer, not a preselected score. Optional rating sliders count only when intentionally answered.
- The common list starts with the **17 documented FGI families**, rather than inventing eight more to reach approximately 25. Admin can change Common membership. The supplied 371-name candidate dataset is illustrative, not a claim about the facility's approved processing scope or all 4,000 possible devices.
- Training and explicitly recorded downtime are not production-weighting minutes. Both remain visible in the labor context. Unknown reported moves are different from zero; partial reported totals are labeled.
- All entered FGI remains **demo** data in this public-demo application, including manual entries. Preset generation changes only the unsaved preview until Save.
- Existing crew structures are extended only for filters and readiness routing. No full workforce scheduler or mandatory lead approval of every shift.
- SAP, SSO, spreadsheets, yield/loss analytics, advanced catalog tooling, and broader workforce management remain deferred by agreement.
- CSV export here is the allocation comparison export; no claim of a general-purpose reporting/export platform. Website-ticket Word exports are retained.

## Migration and data preservation

No relational schema replacement or destructive data migration is required. New document kinds use the existing transactional workspace store:

- Product catalog, unmatched-name review, shifts/events, FGI, allocation revisions, and settings extend the production namespace.
- Catalog initialization is guarded by a migration marker and is transactional.
- Existing metadata-only production ARR/PRR 0.1.0 definitions are archived from the exact prior deployed question definitions, including phase-dependent wording and source-commit provenance. The revised definitions publish as **0.1.1**. Future changes increment ARR and PRR independently.
- Existing entries are not rewritten. Historical reads resolve their original definition, and new records retain a definition snapshot. Unknown historical versions are not reinterpreted using the latest form.
- The old discrete ARR creation endpoint rejects new submissions after the upgrade, directing clients to continuous shifts. Successful old idempotent retries still replay; historical reads, comments, sharing, and linked PRRs remain available.
- No existing accounts, passwords, submissions, ticket statuses, or archive implementation dates are reset by this release. No County data is deleted or mixed into new production metrics.
